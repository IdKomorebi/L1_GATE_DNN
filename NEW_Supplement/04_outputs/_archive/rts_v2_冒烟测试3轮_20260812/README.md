# rts_gmlc_2020_v2

与 `rts_gmlc_2020` 并列。**该目录目前只有说明与方案，尚未执行任何实验。**

---

## 一、为什么要做这个数据集的实验

PJM 数据回答不了审稿人一最要紧的那条意见：**用的全是公开数据，等于用低安全推低安全。**
在 PJM 上我只能人为给字段标密级，标注本身就是主观的。

RTS-GMLC 把这个问题从根上解决了：它的**边界是物理上真实存在的**，不需要人为标注。

| | 候选发布字段 | 敏感目标字段 |
|---|---|---|
| 内容 | 系统级 / 区域级 / 燃料级汇总量 | 具名节点电压相角、具名线路潮流与负载率、具名机组出力与投入状态 |
| 现实依据 | 电网确实公开这类汇总量 | 电网确实不公开这类细粒度运行量 |

除此之外它还提供了 PJM 给不了的两样东西：

**一是真值。** 潮流方程是已知的，所以哪些关系由物理决定、哪些是统计巧合可以判定。
这让本数据集成为**验证方法正确性的唯一手段**——在 PJM 上我们不知道真值，
只能说方法找到了什么，不能说它找得对不对、有没有漏。

**二是可控的扰动。** 1%、3%、5% 三档噪声加在输入端后重新求解潮流（不是给输出加噪），
物理上正确，直接可用于鲁棒性实验。

数据集本身是公开基准（GridMod 的 RTS-GMLC），用固定提交号 `3ece0d3`、官方 2020 时序、
pandapower 的 Newton-Raphson 交流潮流生成，可复现、审稿人认得。

## 二、与 `rts_gmlc_2020` 的差别

### 1. 扩展候选发布字段：27 → 约 80

上一版只有 27 个候选（去掉 3 个全年恒定的还剩 24），而敏感目标有 130 个。
**输入少、目标多，比例是反的**——真实场景是公开字段多、敏感字段少。
24 个候选也撑不起"字段多所以需要初筛"这个叙事：从 24 个里砍掉几个，读者会觉得多此一举。

扩展的全部字段都能从生成脚本已有的数组直接导出（`generator_area`、`variable_costs`、
`renewable` 都已存在），**不需要改动调度环节**，因此不会影响潮流结果的可比性。

#### 现有 27 个

| 类别 | 字段 | 数量 |
|---|---|---|
| 区域与系统负荷（实时 + 日前） | `area_1/2/3_load_actual_mw`、`system_load_actual_mw` 及日前对应 | 8 |
| 系统发电与网损 | `system_generation_mw`、`system_losses_mw` | 2 |
| 区域净送出 | `area_1/2/3_net_export_mw` | 3 |
| 备用 | 调频上/下、三区旋备 | 5 |
| 燃料汇总出力 | 煤、气、核、油、水、风、光、储 | 8 |
| 同步调相机 | `gen_sync_condenser_mw` | 1 |

#### 新增：独立信息类（约 36–40 个）

这些字段携带现有字段没有的信息，不是由已发布字段算出来的。

| 字段 | 数量 | 现实依据 |
|---|---|---|
| **区域 × 燃料发电** `area_{a}_gen_fuel_{f}_mw` | 3×8=24（实际非零约 18–20） | 各调度机构普遍按区域公布燃料结构 |
| **区域网损** `area_{a}_losses_mw` | 3 | 与系统网损同口径；跨区线路损耗按两端各半分摊，规则写进字段字典 |
| **系统边际成本** `system_marginal_cost` | 1 | merit-order 调度的边际机组成本，对应各 ISO 公开的系统电价 |
| **区域边际成本** `area_{a}_marginal_cost` | 3 | 同上，按区域 |
| **可再生可用出力（弃电前）** `avail_wind_mw`、`avail_solar_mw` | 2（系统级）或 6（区域级） | 风光资源预测是常规公开数据 |
| **界面潮流汇总** `interface_ab_mw`、`interface_bc_mw`、`interface_ca_mw` | 3 | 界面级潮流是公开的，线路级才属于敏感 |

#### 新增：派生类（15 个）

这些由已发布字段直接算出，**必然构成恒等式**。加它们**不是为了增加信息量，
而是为第一类检测提供已知真值的验证样例**——我们精确知道存在哪些恒等式，
可以检验方法找得全不全、有没有误报。

| 字段 | 数量 | 构成什么关系 |
|---|---|---|
| 燃料结构占比 `gen_fuel_{f}_pct` | 8 | 比值：占比 = 该燃料出力 ÷ 系统发电 |
| 区域发电合计 `area_{a}_generation_mw` | 3 | 求和：三区之和 = 系统发电 |
| 日前与实时负荷偏差 `area_{a}_load_dev_mw`、`system_load_dev_mw` | 4 | 差分：偏差 = 日前 − 实时 |

**字段字典里必须标注 `derivation = independent / derived`**，
论文里也要说清楚——否则会被质疑"自己造了恒等式再去找恒等式"。
正确的表述是：派生字段模拟真实数据中普遍存在的口径重复（PJM 数据里同样有占比与出力量并存），
它们的作用是给第一类检测提供可核对的答案。

扩展后合计约 **80 个候选发布字段**，与 PJM 的 70 个同量级，初筛这一步才有意义。

### 2. 输出流程按统一规范重做

上一版的产出在内容上没问题，但呈现方式与本项目其余部分不一致：

| 问题 | 上一版的情况 | 本版要求 |
|---|---|---|
| 根目录散文件 | 根目录有 5 个单独文件（一张图、三个 CSV、一个总结） | 根目录只放 `README.md` 与配置 |
| 目录未分类 | 各阶段目录里图、CSV、文档混放，`03_screening` 27 个文件全是 CSV | 每阶段固定 `说明.md` + `figures/` + `data/` |
| 缺门控演化记录 | 只有可行性检查目录下有训练历史，正式定位没存门控值变化 | 每次门控训练都存 `gate_history.csv` 并画演化图 |
| 图不成体系 | 75 张图集中在可行性检查，初筛和定位一张图都没有 | 用 `02_src/plots.py` 的统一绘图模块 |

### 3. 沿用 pjm_2025_v2 的方法设定

两层剥离、λ = 0.005、初筛阈值取零分布 90% 分位——与 `pjm_2025_v2` 保持一致，
这样两个数据集的结果才可比。

### 这个数据集独有的两项验证（其他数据集做不了）

**一、第一类检测的查全率与误报率。** 派生字段构成的恒等式我们精确知道有哪些，
可以直接算：方法找到了几条、漏了几条、有没有把非恒等式误判成恒等式。
**这是全文唯一一处能给出"方法正确性"硬指标的地方。**

**二、推断关系的物理可解释性。** 潮流方程决定了哪些聚合量与哪些节点/线路量有物理耦合。
方法选出的推断源如果与物理耦合一致，说明它找的是真实机理而非数据巧合；
若选出物理上无关的字段，那就是需要解释的误报。
