## 一、这一版要改什么

### 1. 稀疏强度 λ：0.002 → 0.005

四目标扫描结果（排除关注字段、已剥离）：

| λ | 平均选中字段数 | 平均测试 R² |
|---|---|---|
| 0.002（旧） | 16.50 | 0.8675 |
| 0.004 | 12.50 | 0.8878 |
| **0.005（新）** | **11.25** | **0.8879** |
| 0.006 | 10.50 | 0.8839 |
| 0.008 | 9.25 | 0.8796 |
| 对照 STG | 12.50 | 0.8766 |

λ=0.005 精度最高且字段数已比 STG 少 10%。再往上压是纯取舍，
且日前阻塞价会从 0.7425 跌到 0.7062（低于 STG 的 0.7373）——
论文里出现"某目标不如对比方法"的代价大于"平均少两个字段"的收益。

### 2. 剥离改成两层

**第一层：按已知公式剥离，不看残差。** 依据是文档而非数据，不需要阈值。

| 公式 | 涉及字段 |
|---|---|
| 日前电价三分量分解 | 日前总电价、日前能量价格、日前阻塞价、日前边际损耗价 |
| 实时电价三分量分解 | 实时总电价、实时能量价格、实时阻塞价、实时边际损耗价 |
| 净交换功率账目关系 | 净实际交换、净计划交换、净非计划交换 |
| 总交换功率同式 | 总实际交换、总计划交换、总非计划交换 |
| 分燃料出力求和 | 总发电量、十种燃料出力 |
| 备用容量构成 | 主用备用总量、同步备用总量、非同步备用 |
| 功率平衡 | 总发电量、计量负荷、总网损、净实际交换 |

**第二层：逐层剥离，残差门槛 0.10**（不变）。

修的是这个漏洞：日前总电价的 `总电价 ≈ 能量价格` 残差 0.116，刚好高于门槛 0.10 而漏过，
导致"剥离之后"仍有 1 个字段推到 R²=0.9865。它属于官方公式的分量，第一层就该剔除。

### 3. 只跑"排除其余关注字段"两组

| 组 | 说明 |
|---|---|
| `no_screening` | 未初筛 |
| `with_screening` | 经过初筛 |

"含其余关注字段"那两组不再跑——受关注字段互相推断属于循环论证，
论文的主结果本来就是"排除"那一支。

## 二、输出目录：按图 / 文档 / 数据分开

上一版的问题是一个 run 目录里图、说明、CSV 混在一起，而实际只看图和文档。
这一版统一成三个子目录：

```
pjm_2025_v2/
├── README.md                    为什么重跑、与旧版的差别
├── rerun_config.json            全部参数
├── 待执行方案.md                 本文件
│
├── 01_preprocess/
│   ├── 说明.md
│   └── data/
├── 02_class1_identity/
│   ├── 说明.md                  两层剥离各剔除了什么、为什么
│   ├── figures/
│   └── data/
├── 03_screening/
│   ├── 说明.md
│   ├── figures/
│   └── data/
├── 04_source_location/
│   └── <no_screening | with_screening>/run_<时间戳>/
│       ├── 总结.md               ★ 只看这个就够
│       ├── figures/              ★ 所有图
│       │   └── target_<字段>/
│       └── data/                 CSV、门控历史、配置
└── 05_baseline_compare/
    └── <rule1 | rule2 | rule3>/<no_screening | with_screening>/run_<时间戳>/
        ├── 总结.md               ★ 全部目标的对比结论
        ├── figures/
        │   ├── 总览图
        │   └── target_<字段>/
        └── data/
```

原则：**根目录只放 `README.md` 和配置**，不散落任何单独文件；
每个阶段目录下固定三样——`说明.md`、`figures/`、`data/`。

### 文档要写清楚的内容

`总结.md` 面向"只看文档不看 CSV"的读者，必须包含：

1. 这次跑了什么（目标、候选字段数、参数）
2. **结论先行**：选中几个字段、精度多少、与全量和对比方法差多少
3. 选中字段的清单（带中文名和门控值）
4. 每张图说明看什么、能得出什么结论
5. 与上一版（`pjm_2025`）的差异对照

## 四、执行纪律（都是踩过的坑）

1. **启动前先 `pgrep` 检查同名进程**，或依赖 `runlock` 互斥锁。
   曾出现同一命令启动两遍、两进程抢 CPU 跑了 9 小时、机器发烫。
2. **不用 `rm -rf` 清旧结果**。v2 是独立目录，旧结果保留在 `pjm_2025` 作对照。
3. **判断任务是否结束，直接看日志文件最后几行**，不依赖后台通知。
   曾出现通知没回来、干等很久的情况。
4. 长任务串成一个 shell 脚本顺序执行，全程只保持一个 Python 进程。
5. 每完成一个阶段就写该阶段的 `说明.md`，不要攒到最后。

## 五、这一版之后的下一步（不在本方案范围内）

### 把方法合并成一条线

现在的流程里，初筛算出的六个相关系数只用来做"留不留"的二元判断，算完就丢了。
合并之后这六个数直接作为门控的输入：

```
物理规律发现与排除 → 多指标初筛（算六类相关系数）
                          ↓ 相关系数直接进门控
                   引入相关系数的推断源定位
                          ↓
                     留出字段验证
```

这样做有三个好处：

1. **初筛不再是可有可无的前置步骤**，而是定位的必要输入
2. **改进门控不用单独拆一节讲**，它就是方法本身
3. **解决了初筛误删互补字段的矛盾**——初筛的角色从"删除字段"变成"提供特征"，
   不再硬性剔除，由门控在推断误差约束下决定取舍。互补型字段虽然两两相关性弱，
   门控仍可通过 W 的学习给它机会

### 留出字段验证

数据量有限，直接留出 20% 可能偏差大。备选方案是**逐个留一**：
每次只留出一个字段，用其余字段训练门控，再仅凭该字段的六个相关系数预测它是否为推断源，
与完整门控的判定对比。48 个字段就是 48 次，成本可接受，
而且结论更细——能说明对哪类字段的判定可靠、对哪类不可靠。

### 不做的事：最小阻断集

原计划的"最小阻断集与处置代价"这一节**不写**。现在的阻断集是逐层剥离的副产品，
有三处说不过去：贪心不保证最小；依赖 0.10 这个人为门槛（与全文"减少人为设定"的
主张自相矛盾）；没有字段的业务代价权重，"最小"只是个数最少，目标函数本身不合理。

改为：**推断源的规模本身构成风险分级依据**——一两个字段就能推的目标管控成本低，
需要二十个字段共同支撑的屏蔽不可行、只能降精度或延迟发布。方法提供的是风险画像与
量化依据，具体处置由治理方结合业务代价决定。这个表述不引入任何新的主观阈值。
