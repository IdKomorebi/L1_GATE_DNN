# 20260807-01 目录搭建、数据清洗、第一类关系检测

## 动机

原稿被两位审稿人否定定位，需要把论文从"特征选择方法"重构为"数据发布前的推断风险审查"。
新框架把推断关系分成两类：**第一类**是有公式能精确算出来的（账目恒等式、物理定律、
市场规则），**第二类**是没有公式、只能从长期数据里统计出来的隐性推断关系。

第二类才是论文要研究的对象。但要研究它，必须**先把第一类找干净并去掉**，否则后面找
推断源时，模型会一眼挑中这些精确公式关系（它们推断得最准），把真正有价值的统计关系
全部盖住。

本次工作就是把第一类的检测做出来。

## 做了什么

### 1. 新建 NEW_Supplement 目录

与原 NEW_PROJECT 分开，结构如下：

```
NEW_Supplement/
├── 00_docs/        说明与设计文档
├── 01_data/
│   ├── raw/        pjm_2024、pjm_2025（从 NEW_PROJECT 复制，只读）
│   └── clean/      清洗结果
├── 02_src/         dataio.py、identity.py
├── 03_scripts/     01_preprocess.py、02_class1_identity.py
├── 04_outputs/     pjm_<year>/01_preprocess … 06_robustness
└── 05_logs/        本文件
```

数据目录改名为 `pjm_<年份>`：原名 `data2025_Processed_V2` 里的 "Processed" 有误导，
那两个目录只做了时间对齐和联络线汇总，质量问题（全零字段、重复字段、缺失值）在
`Explanation.md` 里只记录了建议、没有执行。前缀 `pjm_` 也方便以后接入别的数据源。

### 2. 数据清洗（03_scripts/01_preprocess.py）

只做机械处理，不做任何需要判据的删除：

- 时间列分离，单独保存供后续按时间切分实验用
- `forecast_load_mw_day_ahead` 缺失约 25%，整列删除
- 缺失率 1% 以下的列按时间线性插值补齐（2025 年是 20 个燃料结构字段各缺 3 个点；
  2024 年是 `forecast_load_mw_latest_available` 缺 12 个点）

输出两个版本，让"删掉那一列"这个决定可以被实验检验：

| 版本 | 2024 | 2025 | 用途 |
|---|---|---|---|
| main | 8784 × 69 | 8760 × 69 | 主实验 |
| allcols | 6539 × 70 | 6558 × 70 | 对照 |

**这一步的直接收益：样本量从 6556 涨到 8760，多了 34%。** 之前所有实验都在 6556 行上跑，
丢掉的三分之一样本全部是为了保住那个缺失四分之一的字段。

全零字段和重复字段**不在这里删**，因为它们是第一类检测的产物，事先删掉等于把方法的
成果偷偷提前用掉。

### 3. 第一类关系检测（02_src/identity.py + 03_scripts/02_class1_identity.py）

七个步骤：

1. **求秩**：把字段摆成表格（末尾加一列全 1 容纳常数项），列归一化后做奇异值分解，
   数有多少个接近零的方向。这个数字是"总共有几条关系"的完整性标尺。
2. **门槛扫描**：从 1e-13 扫到 1e-4，看哪些区间"门槛怎么调条数都不变"。
3. **高斯消元化简**：把抽象的关系变成"某字段 = 某几个字段的组合"的可读形式。
4. **支撑集精简 + 重新拟合**：按"贡献量 = |系数| × 该字段标准差"从小到大试着删项，
   删掉后残差仍在门槛内就真删。这一步去掉了 1e-7 量级的伪系数。
5. **逐字段扫描补足**：化简按列顺序挑主导字段，会把某些关系分配给不合适的字段导致
   写不出来。补一轮逐字段扫描，把漏掉的找回来。
6. **对数空间重跑**：乘除关系取对数后变成加减关系，用同一套流程捕获比值型和乘积型。
7. **跨年复验 + 已有公式验算 + 反复剥离**。

**两个门槛必须分开设**（这次改的一个重要问题）：

- `tol_rank = 1e-5` 比较的是归一化奇异值比，用来数条数，负责**不漏**
- `tol_resid = 1e-3` 比较的是某字段自身的相对残差，用来判断关系写出来是否成立，负责**不错**

两者量纲不同。之前共用一个数，导致日前电价分解（残差 1.5e-8，明显是真关系）因为
奇异值比不够小而被漏掉。

## 结果

### 门槛扫描

| 门槛 | 条数 | | 门槛 | 条数 |
|---|---|---|---|---|
| 1e-13 | 11 | | 1e-08 | 12 |
| 1e-12 | 11 | | 1e-07 | 12 |
| 1e-11 | 11 | | 1e-06 | 13 |
| 1e-10 | 11 | | 1e-05 | 15 |
| 1e-09 | 12 | | 1e-04 | 16 |

有两段平台（1e-13~1e-10 是 11 条，1e-09~1e-07 是 12 条）。

**但平台不能单独用来定门槛**——真正的公式关系要到 1e-5 才全部出现。所以改成：求秩门槛
放宽、宁可多给候选方向，再用残差、跨年复验和系数整齐程度去筛。这个调整比"找平台"更稳。

### 检测到的关系（求秩 1e-5 给出 15 条，全部写出成立）

**恒定字段 5 个**（整年取值不变，不携带任何信息）：
`gen_fuel_storage_pct`、`da_as_mcp_thirty_minutes_reserve`、`da_as_ircmwt2_primary_reserve`、
`da_as_ircmwt2_synchronized_reserve`、`da_as_ircmwt2_thirty_minutes_reserve`

**完全重复字段 5 组**：`da_as_total_mw_*` 与 `da_as_as_mw_*` 三组、`da_as_ss_mw_*` 三列相同（2 组）

**真正的公式关系 5 条**，按跨年表现和系数整齐程度分成三档：

| 档次 | 关系 | 本年残差 | 跨年 |
|---|---|---|---|
| 恒等式 | `净实际交换 = 净计划交换 − 净非计划交换` | 2.0e-15 | 2.2e-15 |
| 恒等式 | `日前能量价格 = 日前总电价 − 阻塞价 − 网损价` | 1.5e-08 | 2.6e-08 |
| 恒等式 | `非同步备用 = 主用备用总量 − 同步备用总量` | 2.2e-05 | 9.2e-06 |
| **规则型** | `主用备用需求 = 1.49995 × 同步备用需求 − 94.9` | 8.6e-05 | **3.9e-02** |
| 近似关系 | `实时能量价格 = 0.994 × 阻塞价 + 0.999 × 总电价` | 1.9e-04 | 3.4e-04 |

两条值得单独说：

- **规则型那条是新发现**。系数 1.49995 就是 PJM"主用备用需求等于 1.5 倍同步备用需求"
  这条市场规则。它在 2025 年精确成立，换到 2024 年残差退化 450 倍——说明规则改过。
  这类关系和物理恒等式性质不同：**规则一改它就失效，基于它的管控措施需要定期复核**。
- **实时电价那条系数不整齐**（0.994、0.999），而日前那条系数是干净的 ±1。原因是实时
  数据发布精度更粗。这正好说明"系数整齐程度"作为判据是有效的。

### 比值型与乘积型（线性方法完全抓不到）

- 燃料占比 = 该燃料出力 / 各燃料出力之和，残差 1.2e-02 ~ 9.6e-02
- **`调频信用额 = 调频价格 × 调频购买量`，残差 4.8e-02** —— 官方文档没写，自动发现的

### 已有公式验算

| 公式 | 原样 | 口径标定后 |
|---|---|---|
| 日前电价三分量分解 | 1.4e-08 | 1.4e-08 |
| 实时电价三分量分解 | 5.8e-05 | 5.8e-05 |
| 净交换功率账目关系 | 1.6e-16 | 2.0e-15 |
| 总交换功率同式（对照） | 6.4e+00 | 6.1e-01 |
| 分燃料出力求和 | 1.2e-01 | 6.6e-02 |
| **功率平衡（教科书写法）** | **4.98e-01** | **3.7e-03** |
| 功率平衡（符号修正） | 2.7e-02 | 3.7e-03 |

**教科书写的功率平衡在实际发布数据上根本不成立**（残差 0.498），符号修正后降到 0.027，
允许标定系数后才到 0.0037。标定出的网损系数几乎为零，说明计量负荷的口径已经含了网损。

这一条同时回答两位审稿人：对审稿人一，"物理定律能推多少"这个问题本身需要方法来回答，
查手册不够；对审稿人二，这是"数据口径差异影响结果"的实测证据。

### 反复剥离

| 目标 | 删除 |
|---|---|
| 净实际交换功率 | 净计划交换功率 |
| 日前总电价 | 日前能量价格 |
| 日前阻塞价 | 日前总电价 |
| 计量负荷 | 无 |
| 总发电量 | 无 |

计量负荷和总发电量没有任何精确公式能算出来——它们此前 0.999 的高精度是**统计关系**，
不是公式关系。这两个正是第二类研究的好对象。

## 对论文的影响

1. **字段数要改**：70 个字段里 5 个恒定、5 个重复，真正携带独立信息的只有 60 个。
   原稿说的"69 个候选字段"需要修正。重复字段还会让门控网络把权重分摊到两个一模一样的
   输入上，影响特征重要性排序，所有涉及字段数的结论都要重算。
2. **样本量涨 34%**（6556 → 8760）。
3. **公式关系分三档**（恒等式 / 规则型 / 近似关系）是数据自己呈现出来的，不是事先设定的，
   可以作为论文第 3 章的一个结果。
4. `configs/data2025_v2.yaml` 里手工写的 `exclude_columns` 现在有了算法依据，
   审稿人追问"凭什么排除这些字段"有答案了。

## 需要注意的既有事实

`01_data/raw/pjm_2025/Explanation.md`（之前人工体检的记录）里已经列出了全零字段、
重复字段和电价分解关系。所以这些不是本方法首次发现，而是**方法自动复现了人工体检的结论**。
方法额外找到的是：关系总条数这个硬指标、备用需求的规则型关系、调频信用的乘积关系、
以及功率平衡的口径问题。

论文里应该用人工清单当参照系来写——"方法能不能全部复现、还能不能多找出来"比
"我们提出了一个方法"有说服力。
