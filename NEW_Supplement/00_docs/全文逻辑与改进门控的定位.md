# 全文逻辑：两步够不够，改进门控放在哪

---

## 一、两步不够，缺第三步

现在的链条是：

```
场景：数据发布前的分级与风险评估
  ↓
第一步：剥离已知公式（官方公式 + 自动发现的恒等式与近似关系）
  ↓
第二步：定位隐性推断源
  ↓
（停在这里）
```

停在第二步，方法的输出是"**这 11 个字段能把目标推到 0.97**"。

但发布方要做的决策不是这个。他要回答的是：

- 这批字段能不能发？
- 如果发，要不要处理（降精度、延迟、聚合）？
- 如果要阻断，屏蔽哪几个字段代价最小？
- 处理完之后，还剩多少风险？

**所以缺的是把分析结果翻译成决策的那一步。** 补上之后链条是：

```
第一步：剥离已知公式
  ↓ 作用：把"已知的、规则可枚举的风险"与"未被认识的风险"分开
第二步：定位隐性推断源
  ↓ 作用：把"能不能推"变成"哪些字段在推"，并给出风险的集中程度
第三步：最小阻断集与处置代价          ← 新增
  ↓ 作用：回答"该管哪几个"和"管了要付出什么代价"
第四步：增量字段的快速判定            ← 改进门控的位置
       作用：字段陆续增加时，不必每次重训整个模型
```

第三步的机制其实已经有了，只是没有用治理的语言组织输出：
逐层剥离本质上就是在求阻断集，Top-n 再训练给出的就是残余风险。
需要做的是把它们从"方法验证"重新表述为"处置建议"，并配一张效用—风险权衡曲线。

## 二、为什么必须定位隐性推断源

这一点要在论文里正面回答，否则读者会问"知道能推断不就够了吗"。三条理由：

### 1. 不定位就做不出决策

"目标可被推断"是一个是非题，发布方拿着它没法行动——不知道该管哪个字段。
只有定位到具体字段，才能作出"哪几个字段不得同时发布"这样的判断。

### 2. 推断源的规模本身就是风险等级的一个维度（这条最有力）

同样是"可推断到 0.97"，两种情况的治理含义完全不同：

| 情况 | 治理含义 |
|---|---|
| 1–2 个字段就能推 | 屏蔽成本极低，管住那一两个即可，风险可控 |
| 需要 20 个字段共同支撑 | 屏蔽几乎不可行，只能靠降精度或延迟发布 |

`pjm_2025` 的结果里这两类都有：计量负荷在四种设定下都是**一个字段**就推到 0.9998；
总实际交换功率、实时阻塞价则需要 20 个以上。

**"能不能推"是是非题，"要几个字段才能推"是连续量。** 后者的信息量大得多，
而且直接对应治理成本。这是定位这一步不可替代的价值。

### 3. 定位是类型判定的前提

要判断一条推断关系是公式型还是统计型、是稳定的还是只在某段时间成立，
必须先有一个**具体的字段集合**作为检验对象。对全量模型做稳定性检验没有意义——
它在每个时段可以靠不同的字段达到好成绩，整体看着稳，实际没有任何一条关系是稳的。

## 三、改进门控要不要保留：保留，但换个定位

原稿把改进门控（相关性驱动的门控，`g_i = σ(Wᵀ R_i + b)`）当作贡献点二，
卖点是"能看出哪种相关系数对判定贡献更大"。

**这个卖点弱**，而且与场景关系不大——发布方不关心是 Pearson 还是 HSIC 更重要。

### 真正有价值的是另一条：新字段无需重训即可判定

治理场景里字段是**陆续增加**的。数据共享方今天新增一列，明天再加一列。
如果每来一个新字段都要把整个门控模型重训一遍才能知道它会不会制造新风险，
成本高到不现实。

改进门控把判定压缩成两步：**算这个新字段与目标的 6 个相关系数 → 代入已学到的 Wᵀ R + b**。
秒级完成，不需要任何训练。

**这是 STG 和 D-Gating 都做不到的。** 那两种方法的门控参数是与具体字段一一绑定的，
只能对训练时见过的字段给出判定；来了新字段，参数里没有它的位置，只能重训。
改进门控学的是"从相关性证据到推断贡献"的映射，这个映射对任何字段都适用。

用户提到 STG 与 D-Gating 在"二分化的特征选择"这一点上确实雷同——
**改进门控恰恰是拉开差距的地方，它做的是另一件事。**

### 但必须诚实说明它的固有局限

改进门控只使用**两两相关性**作为输入，所以它必然漏掉"单独看与目标关系弱、
和别的字段组合起来才强"的那类字段——而这恰恰是隐性推断最值得关注的情形。

（这一点在初筛实验里已有实证：初筛按两两相关性筛选，导致净实际交换在排除关注字段的
设定下，全量 R² 从 0.9674 掉到 0.9020，说明确实误删了有贡献的字段。）

所以它**不能替代主方法**。正确的分工是：

| | 承担什么 | 用在什么时候 |
|---|---|---|
| 主方法（剥离 + D-Gating 定位） | 精查 | 一次性的完整审查 |
| 改进门控 | 快筛 | 后续增量字段的初步判定 |

快筛给出"可能有风险"的信号后，再走一遍精查确认。这样既控制了成本，
又不会因为快筛的局限而漏掉互补型字段。

### 建议补一个能验证这个主张的实验

现在改进门控的价值只是说出来的，没有实验支撑。建议做**留出字段验证**：

1. 从候选池里留出若干字段（比如 20%），不参与改进门控的训练
2. 用剩下的字段训练出 W 和 b
3. **仅凭留出字段与目标的 6 个相关系数**，预测它们是否为推断源
4. 与主方法（D-Gating 在全部字段上的判定）对比，报告命中率与漏报率

这是一个**可证伪的主张**，比"提供可解释的相关性权重"实在得多。
如果命中率高（比如 80% 以上），"新字段快速判定"这个卖点就成立；
如果低，那就如实报告并把改进门控降为附录。

## 四、按这个逻辑重排的章节结构

```
1 引言
  1.1 电力数据分级共享的需求与逐字段定级的盲区
  1.2 组合推断风险：一个规范失语的场景
  1.3 相关工作与本文贡献

2 问题定义
  2.1 发布审查问题与保护边界
  2.2 两类推断关系：有公式可循的与没有的
  2.3 判据与评估协议

3 方法
  3.1 已知公式的剥离（官方公式清单 + 零空间自动检测 + 逐层剥离）
  3.2 D-Gating 推断源定位（含阈值不敏感的论证）
  3.3 最小阻断集与处置代价                    ← 新增，把分析变成决策
  3.4 相关性驱动的增量字段快速判定             ← 改进门控，重新定位

4 实验
  4.1 设置：数据、保护边界、评估协议
  4.2 第一类关系的检测与剥离结果
  4.3 隐性推断源定位与验证（含风险集中度分析）
  4.4 同预算基线对比（三条规则）
  4.5 增量字段快速判定的留出验证              ← 新增
  4.6 鲁棒性与泛化性
  4.7 处置建议与效用—风险权衡

5 结论与局限
```

### 关于篇幅

用户担心"篇幅集中在推断源寻找上会头重脚轻"。按上面的结构，
3.1（剥离）、3.2（定位）、3.3（阻断与处置）大致均衡，
3.4 作为一个较短的补充。实验部分 4.2/4.3/4.4 是主体，4.5/4.6/4.7 各占一小节。

如果仍然超长，**优先压缩初筛那一节**——已有实证表明它会误删互补型字段，
而 58 个字段直接进门控在计算上毫无压力，它的存在价值主要是流程完整性。
