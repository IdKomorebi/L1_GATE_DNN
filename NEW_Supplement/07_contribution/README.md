# 07_contribution：随机屏蔽下的字段贡献值

这是一个自成一体的小项目，目标是给发布前审查提供一个比"最小充分集合"更细的答案：
**候选池里每个字段各自贡献了多少推断风险，以及它属于哪一类风险。**

对 `NEW_Supplement/02_src/` 只做**只读复用**，不修改那边任何文件；
产物全部落在本目录的 `outputs/` 下，不写进 `04_outputs/`。

---

## 一句话说清在做什么

现有方法回答"有没有一组字段够用"，本目录回答"每个字段各占多少份"。

做法是训练一个模型，让它每一步看到的输入都被**随机屏蔽**掉一部分字段，
于是它学会在任意字段组合下都尽力还原目标。训练完，查任何一个字段组合的
还原能力只要做一次前向——一次训练，2^46 种组合任意可查。
再用 **Shapley 值**（合作博弈论里"把总量分摊给各参与者"的唯一公平分法）
把总还原能力分摊到每个字段头上。

---

## 为什么需要它

三条来自本仓库的实测证据：

1. **没被选中的字段照样能推。** PJM 选中集合重训 R² 0.8512，未选中 0.7905，
   只差 0.061；RTS 上未选中甚至高 0.0002。
2. **只处置推断源等于没处置。** 只对选中字段做处置、其余照常发布时，
   整体可推断性 RTS 只降 0.007，PJM 反而升 0.012。
3. **选中集合不稳定。** 只换随机种子，Jaccard 只有 0.46~0.61，选中数 8~12 跳，
   而全量 R² 稳到 ±0.0012。

根子是定义：最小充分集合只要够用就行，有多条路径都够用时挑哪条本来就没唯一答案。

---

## 输出的四个数

对每个候选字段给出：

| 量 | 含义 |
|---|---|
| **贡献值** | 它该分到多少份还原能力（所有字段之和 = 全部发布相比只知道历史均值多出来的能力） |
| 独立能力 | 只发布它一个，能推出多少 |
| 不可替代性 | 全部发布、单独抽掉它，损失多少 |
| **协同–冗余指数** | 不可替代性 − 独立能力 |

指数的刻度由三种极端情形定死（已用解析解验证）：

- **−1 完美替身**：有别人顶着，删了它也没用
- **0 独立可加**：贡献和别人无关
- **+1 纯协同**：只有和别人配合才值钱，单独看什么都看不出来

两个维度合起来是一张风险坐标图：横轴看这个字段值多少，纵轴看它属于哪一类。

## 怎么跑

```bash
PY=~/miniconda3/envs/Pytorch310_MacBookAir/bin/python

$PY scripts/00_selftest_shapley.py            # 先自检，必须全过
$PY scripts/04_truth_synthetic.py             # 人造真值，五道题
$PY scripts/07_truth_real.py --dataset rts_v2 # 真实真值
$PY scripts/12_full_run.py --dataset rts_v2   # 主实验
$PY scripts/13_stability.py --dataset rts_v2  # 稳定性

$PY scripts/16_gate_blindspot.py --run <主实验>/data/contributions_all.csv

$PY scripts/19_refigure.py        # 从表重出全部图

```

从不覆盖；作废的结果移到 `_archive/` 而不是删掉。

## 验证做到哪一步

| 级别 | 内容 | 结论 |
|---|---|---|
| 算法自检 | 四个有解析答案的玩具例子 | ✓ 精度 1e-10 |
| L0 | 代理模型 vs 真实重训 | ✓ 差值偏差 0.0495，落在参照答案自身噪声（0.040~0.048）内 |
| L3 | 五道人造真值题（穷举精确解） | ✓ 全过，含纯协同与纯替身两道判别题 |
| L1 | 公理自检（对称/零贡献/加和） | 加和性到机器精度；对称性有残余误差，见下 |
| L2 | 已知精确路径（RTS 仿真自带） | 部分通过，三个口径并排报，含对本方法不利的一栏 |
| L4 | 重训认证（仓库既有口径） | k=1 最好；但门控/Lasso 用更少字段达到全量九成 |
| L5 | 换种子稳定性 | ✗ **原主张未成立**，见下 |
| — | 剥离之后盲区还在不在 | 站住但要收窄，见 `logs/20260815_09` |

### 三条要如实说的短板

1. **对称性不为零**。46 维时代理模型对两列**逐个数完全相同**的字段会给出不同的
   还原能力（原始 0.071，调参后 0.011~0.03）。原因是"只发布某一个指定字段"
   在训练样本里占比极低，而它恰恰是 Shapley 权重最高的地方。已通过加大权重衰减
   （3e-3）和改掩码规模分布（按 Shapley 核）部分缓解。
   作为对照，同一道题上分解式门控的同组差异是 **100%**、Lasso 是 97%。

2. **稳定性的主张没有站住**。原设想"集合不稳定但份额稳定"，实测本方法的排序
   秩相关 0.785、门控 0.807——**门控反而更稳**（其中两个目标它只选 1 个字段，
   属于白送的满分；排除后是本方法 0.796 对门控 0.710，略优但幅度不大）。
   站得住的只有一条：贡献值本身的相对波动只有 1.6%~5.1%。

3. **协同型字段在真实数据上几乎找不到**。人造题证明了方法有这个能力
   （纯协同题给出 +0.98/+1.04，和理论值吻合），但 RTS 上只有 0~6 个，
   **PJM 上 12 个目标全部为 0**。这个卖点基本没兑现。

### 一次做错并更正的地方

最初用时序划分跑 PJM，报了"交换功率类目标 v(全部) 为负，推不出来"。
**错了**——那三个负数是随机屏蔽代理模型自己的能力上限（摊销代价），
不是可推断性；专训普通网络能到 0.34。已在 `logs/20260815_08` 和
`docs/方法说明与结论综述.md` 3.8 节写明更正，并在主脚本里加了强制校验：
每个目标都查一次"专训网络 R² 减 v(全部)"，超过 0.10 就打警告并标为不可分析。

## 几条纪律

- 不重做仓库已证否的三条路：相关系数生成门控、热启动增量、多相关性初筛。
- 不做最小阻断集。贡献值是连续量，不产出"删了就阻断"的清单。
- 不引入新的主观旋钮：判零门槛由同池的噪声字段量出，采样量由有确切答案的
  对称性标尺定出。
- 结论里不写死论文立场（推断源唯不唯一这件事另一个 session 正在和用户确认）。
