## 2. 用户提出的几个主要问题

### 2.1 初筛效果太弱

原始初筛阈值较低，候选特征基本没有筛掉几个。用户希望提高初筛阈值，让初筛看起来更有作用，但不希望使用 `pass_count >= 2` 这种形式。

最后采用的解释口径是：

> 只要任意一种统计依赖指标达到阈值，就纳入候选特征，即 `pass_count > 0`。

这样在论文里更容易解释为“只要捕捉到一种统计依赖，就保留为候选变量”。为了让初筛确实能筛掉一部分变量，调整了 6 种相关/依赖指标的阈值。

当前 `NEW_PROJECT/configs/data2025_v2.yaml` 中保留的初筛阈值为：

```yaml
relations:
  thresholds:
    nmi: 0.06
    spearman: 0.15
    pearson: 0.15
    kendall: 0.12
    distance_corr: 0.20
    hsic: 0.25
```

这组阈值对 `net_actual_interchange_mw` 的 combo5 中心实验大致表现为：

- 原始候选关系：67 个
- 初筛保留：55 个
- 筛掉：12 个
- 各指标通过数量大致为：
  - NMI：23
  - Spearman：33
  - Pearson：25
  - Kendall：29
  - Distance correlation：27
  - HSIC：31

该结果比原始阈值下筛掉很少的情况更适合论文叙事。

### 2.2 冗余实验不适合做全量消融

由于新数据中 X 特征很多，逐个做冗余消融不现实。因此讨论后形成了新的实验叙事：

- L1GateDNN 找到一组关键特征，例如 18/19/20 个。
- 不必逐个删除做全消融。
- 可以测试 Top-5、Top-10、Top-15、完整选中特征、全量候选特征、未选中特征等组合。
- 目标是说明：
  - 特征太少时推断准确率下降。
  - 关键特征集已经接近最小有效集合。
  - 关键特征集性能接近甚至超过全量特征。
  - 未选中特征单独推断明显较弱。

此前基于原始 L1 run 的一个验证结果是：

- Top5 R2：约 0.473
- Top10 R2：约 0.935
- Top15 R2：约 0.965
- Selected18 R2：约 0.970
- Full59 R2：约 0.966
- Unselected41 R2：约 0.811

这个结果支持“少量关键特征基本达到甚至超过全量特征”的论文叙事。

### 2.3 Baseline 对比实验的公平性问题

用户担心：baseline 对比实验中，每个中心数据的 `n` 是由 L1DNN 筛选出来的特征数决定的，然后其他方法也固定这个 `n`，这样感觉 baseline 不完全独立。

讨论后的建议口径：

- 主实验可以保留“固定 n”的对比，因为它体现的是“在相同特征预算下，不同特征选择方法的预测能力”。
- 但论文中需要明确写出：
  - `n` 来自主方法 L1GateDNN 的特征数量。
  - 这是为了控制特征数量预算，而不是让各方法自行选择任意数量。
- 如果需要更强的公平性，可以补充：
  - 固定多个预算：Top-5、Top-10、Top-15、Top-n。
  - 或对每种方法做 K-sweep 曲线，比较不同 K 下的性能变化。

关于“小量特征性能超过全量特征”的解释建议：

- 全量特征中可能包含冗余变量、弱相关变量和噪声变量。
- 少量关键特征可降低模型复杂度与过拟合风险。
- 对中心变量有直接统计依赖或物理/市场耦合关系的特征，可能比全量输入更稳定。

## 5. 改进门控 loss 逻辑检查

用户指出旧项目中：

```text
complete_test3_DateAssociation\MetaGatingModelOutput\BasedOnData4\CenteredOn电压节点消耗功率(epochs=200,lambda=0.05,active=0.06)\gate_params.png
```

这个旧图看起来也像普通 L1 的 gate 变化图，因此怀疑新旧项目的 improved gate loss 逻辑是否一致。

检查了以下脚本：

- `complete_test3_DateAssociation/MetaGating_CenterDataPredictor.py`
- `complete_test3_DateAssociation/MetaGating_L2Risk_CenterDataPredictor.py`
- `complete_test3_DateAssociation/MetaGating_SoftRisk_CenterDataPredictor.py`
- `NEW_PROJECT/src/models.py`
- `NEW_PROJECT/src/trainer.py`

结论如下。

### 5.1 旧项目 MetaGating_CenterDataPredictor.py

旧 `MetaGating_CenterDataPredictor.py` 的 gate 形式：

```python
g = sigmoid(R_norm @ W_meta + b_meta)
```

loss：

```python
mse + lambda_l1 * mean(abs(gates))
```

也就是说，旧项目这个 MetaGating 本质上是对生成出来的 gate `g` 做 L1 惩罚，不是惩罚 `W_meta`。因此它本来就会呈现类似普通 L1 gate 的下降效果。

旧脚本还有几个特点：

- `correlation_vectors` 做 Z-score 标准化。
- `W_meta` 初始化为 `torch.rand(6,1)-0.5`。
- `W_meta` 学习率设置为 `cfg.lr * 5`。
- 典型 `lambda_l1` 为 `0.03` 或 `0.05`。
- `active_threshold=0.06` 只是统计活跃数的阈值，不直接参与 loss。

### 5.2 新项目 ImprovedL1GateDNN

新项目 `ImprovedL1GateDNN` 当前逻辑：

```python
g = sigmoid(R_norm @ W_meta + b_meta)
loss = mse + lambda_l1 * mean(abs(g))
```

warmup 逻辑：

```python
lambda = 0 if epoch <= warmup_epochs else lambda_l1
```

所以，新项目 ImprovedL1 和旧项目 MetaGating_CenterDataPredictor 的正则对象都是 `g`，不是 `W_meta`。

差别主要在默认超参数上：

- 新项目原始 `W_meta` 初始化为 0。
- 新项目原始 `lambda_l1=0.001`。
- 新项目原始没有 `meta_lr`，即 meta 层学习率等于普通 `lr`。
- 新项目原始 `active_threshold=0.06`。

### 5.3 新项目 ImprovedL2GateDNN

新项目 `ImprovedL2GateDNN` 当前逻辑：

```python
loss = mse + lambda_l2 * mean(g ** 2)
```

它也是惩罚 gate `g`，但 L2 惩罚更平滑，不像 L1 那样强推稀疏。

### 5.4 旧项目 SoftRisk

旧 `MetaGating_SoftRisk_CenterDataPredictor.py` 和上述两者不同。

它的 loss 是：

```python
mse + lambda_l2 * (mean(W_meta ** 2) + 0.1 * mean(b_meta ** 2))
```

也就是说，它惩罚的是 `W_meta/b_meta`，不是直接惩罚 gate `g`。这个版本更像“平滑风险映射”，不适合作为 L1-like gate 曲线的直接对比。

## 6. 关于 warmup 的确认

用户问：新项目的改进门控最一开始是否就有 warmup，还是本轮刚加的。

  warmup_epochs: 50

ImprovedL2GateDNN:

所以 warmup 不是本轮改动引入的。

## 7. 超参数尝试与否定方案

为了让 ImprovedL1 的 gate 变化更像旧项目中的曲线，曾尝试过比较激进的改法：

- `W_meta` 从 0 初始化改为随机初始化 `torch.rand(...)-0.5`
- `lambda_l1` 调到 `0.03`
- 增加 `meta_lr=0.005`
- `active_threshold` 改为 `0.50`
- ImprovedL2 也尝试过 `lambda_l2=0.01`、`meta_lr=0.006`

实验结果说明该方案不合适，尤其是 ImprovedL1。

### 7.1 激进参数结果

`lambda_l1=0.03`：

- best R2：约 0.972858
- 但按 0.5 阈值，最终选中特征为 0
- gate 被全部压到 0.5 以下，不适合论文解释

`lambda_l1=0.01`：

- best R2：约 0.972642
- 100 epoch 时约 17 个特征高于 0.5
- 150 epoch 时约 6 个
- 200 epoch 时仍变成 0
- 依然过强

`lambda_l1=0.003`：

- best R2：约 0.971732
- 最终约 17 个特征高于 0.5
- 比 0.01/0.03 合理，但仍偏向较强筛选

最终用户认为“超参数太大，对 ImprovedL1 太离谱”，因此把相关改动调回。

### 7.2 已恢复的内容

已恢复：

- `NEW_PROJECT/src/models.py`
  - `W_meta` 恢复为 `torch.zeros(cor.shape[1], 1)`
- `ImprovedL2GateDNN`
  - `lambda_l2` 恢复为 `0.001`
  - 去掉 `meta_lr`
- 不再使用 `lambda_l1=0.01/0.03` 这类过大参数

## 8. 当前推荐的小幅调整方案

恢复原始参数后，又做了小幅尝试。

原始 ImprovedL1：

- `lambda_l1=0.001`
- 按 `active_threshold=0.06` 输出时，几乎所有 sigmoid gate 都会被算作活跃，因此 `selected_features.json` 会显示 55/55。
- 如果按更合理的 sigmoid 风险边界 `0.5` 统计，大致是：
  - epoch 50：27
  - epoch 100：25
  - epoch 150：22
  - epoch 200：21
- best R2：约 0.971120

小幅调整 ImprovedL1：

```yaml
ImprovedL1GateDNN:
  lambda_l1: 0.0015
  warmup_epochs: 50
  active_threshold: 0.50
```

最终一致版 run：

```text
E:\L1_GATE_DNN\NEW_PROJECT\outputs\data2025_Processed_V2\CenterOn_net_actual_interchange_mw\ImprovedGateDNN\ImprovedL1GateDNN\run_20260602_1550_combo5_ImprovedL1_lam0p0015_thr0p5
```

结果：

- best R2：0.971558
- best epoch：174
- final R2：0.971558
- final selected：20
- best epoch selected：21
- active 变化：
  - epoch 50：27
  - epoch 100：24
  - epoch 150：21
  - epoch 174：21
  - epoch 200：20
- final gate 分布：
  - min：0.1136
  - median：0.4049
  - max：0.7533

这个方案相对克制，只比原始 `lambda_l1=0.001` 高 50%，不会把 gate 全部压没，同时能让输出文件直接以 `0.5` 作为风险阈值进行选中特征统计。

当前建议使用这个小幅调整版作为 ImprovedL1 的默认参数。
